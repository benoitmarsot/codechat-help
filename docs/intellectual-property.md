# How LiquidAmber Handles Your Intellectual Property

LiquidAmber is designed to help newsrooms research, organize, and use their authorized content while preserving editorial control over that content. This page explains how LiquidAmber uses AI, customer data, and memory.

## Your data is not used to train AI

LiquidAmber does not train its AI models on customer conversations, archives, or other customer content. When you ask a question, LiquidAmber retrieves information relevant to that question and provides it to an AI model as context for that specific request. The model uses the context to formulate an answer. This is not the same as training the model.

LiquidAmber has commercial agreements with Google, OpenAI and Anthropic, which - unlike consumer models - disallow using customer content to train their models.

## Training and context are different

**Training** changes or improves a model using data over time. LiquidAmber does not use customer content for this purpose.

**Context** is the limited information supplied with an individual request so the model can answer that request. For example, LiquidAmber may provide relevant articles, records, or conversation details alongside your question. That context is used to generate the response to that request, not to train the underlying model.

## LiquidAmber does not send your entire archive to an AI provider

LiquidAmber controls which information is retrieved and included for a particular request. AI providers do not receive unrestricted access to a customer's full archive, CMS, or internal systems.

Depending on the question, LiquidAmber may retrieve a limited set of relevant materials, such as articles from an authorized archive, documents added to a project, or sources selected during research. Only the material needed to help answer the request is included as context.

## What LiquidAmber stores

LiquidAmber stores the application data needed to provide its services, including authorized connections, projects, discussions, and any resources a customer chooses to make available through the platform. This data remains subject to LiquidAmber's access controls and permissions.

LiquidAmber can also retain limited information as memory when memory is enabled. Memory is application data stored by LiquidAmber, not model training data.

## How memory works

Memory can preserve useful context between conversations, such as a reporter's preference or a definition specific to an investigation. It is scoped either to an individual user across their eligible work or to that user within a specific project.

Memory is selectively supplied as context in a later conversation when it is relevant. It does not give a model unrestricted access to a user's content, and it is not used to train an AI model. Users can review, update, or delete their memories. See [Personal Memory](personal-memory.md) for details.

## Permissions and isolation

LiquidAmber applies user, project, organization, and outlet permissions when retrieving content. Access to one project or outlet does not automatically provide access to another. Project-scoped work and memory remain within their applicable permissions and boundaries.

## Your editorial control

LiquidAmber is designed to support journalists and newsroom teams, not replace their reporting, verification, attribution, or editorial judgment. You retain control over which sources are connected, which materials are available to a project, and how AI-generated assistance is used in the final work.
